## 🔴 현재 Journey (문제점 발견)

### Step 1: 원본 영상 선택
민지: "이 90년대 로맨스 영상 오마쥬하고 싶다!"
→ 영상을 빌더 1에 업로드

### Step 2: 빌더 1 결과 확인
민지: "오... 씬 분석이랑 프롬프트가 나왔네"
→ 빌더 2로 전달

### Step 3: 빌더 2 결과 수령
민지: "4개 파일이 왔네... 오마쥬_IMAGE, 오마쥬_MOTION, 변주_IMAGE, 변주_MOTION"

### Step 4: 첫 번째 파일 열기 (오마쥬_IMAGE.md)
```
(스크롤 스크롤...)
음... Scene 01 프롬프트... Scene 02 프롬프트...
```

### Step 5: 🔴 혼란 시작
민지: "어... 그냥 Scene 01부터 하면 되나?"
→ Scene 01 Midjourney 프롬프트 복사
→ Midjourney에 붙여넣기
→ 이미지 생성

**문제 1:** ANCHOR 씬을 먼저 안 만들어서 캐릭터 일관성 깨짐

### Step 6: Scene 02 생성
→ 다른 남자 얼굴 나옴

**문제 2:** "어? Scene 01이랑 Scene 02 남자가 다르게 생겼는데?"

### Step 7: --cref 개념 모름
민지: "프롬프트에 --cw 100 이런 거 있는데... cref는 뭐지?"
→ 검색해봄
→ "아... 레퍼런스 이미지를 먼저 만들어야 하는구나"
→ 처음부터 다시 시작 😫

**문제 3:** 시간 낭비 + 좌절감

### Step 8: MOTION 파일 열기
민지: "이제 모션이네... 근데 IMAGE랑 씬 번호 찾아가며 매칭해야 하네"
→ 두 파일 왔다갔다
→ 복사 붙여넣기 피로

**문제 4:** 파일 간 점프 필요

### Step 9: 변주 버전 시작
민지: "변주도 해볼까? 또 파일 2개 열어야 하네..."

## 🟢 개선된 Journey (제안)

### Step 1-3: 동일

### Step 4: 통합 워크플로우 파일 열기 (오마쥬_WORKFLOW.md)

```markdown
## 🌟 STEP 0: 앵커 이미지 먼저!
→ Scene 02 프롬프트 [복사]
→ Scene 05 프롬프트 [복사]
```

민지: "아! 앵커 먼저 만들라는 거구나"
→ Scene 02 이미지 먼저 생성
→ Scene 05 이미지 생성
→ URL 복사해둠

### Step 5: 나머지 씬 순서대로

```markdown
## 📍 Scene 01: 남자의 등장

### 🖼️ IMAGE
[프롬프트... --cref [여기에 MALE_ANCHOR_URL] ]
[📋 복사]

### 🎥 MOTION
[프롬프트...]
[📋 복사]
```

민지: "씬마다 IMAGE랑 MOTION이 같이 있네! 편하다"
→ 앵커 URL 붙여넣고 이미지 생성
→ 바로 아래 MOTION으로 영상 생성

### Step 6: 체크리스트로 진행 상황 확인

```markdown
## ✅ 진행 체크리스트
- [x] Scene 02 앵커 이미지
- [x] Scene 05 앵커 이미지
- [x] Scene 01 이미지 + 모션
- [ ] Scene 02 모션만 (이미지는 앵커에서 완료)
...
```

### Step 7: Academy 웹 도우미 활용 (선택)
민지: "웹에 붙여넣으니까 카드 형태로 보여주네! 복사 버튼도 있고"

## 💡 핵심 인사이트

### 1. 앵커 퍼스트 (Anchor First)
- 현재 워크플로우에서 가장 큰 병목
- 앵커 없이 시작하면 처음부터 다시 해야 함
- **반드시 앵커 단계를 맨 앞에 명시**

### 2. 씬 단위 묶음 (Scene Bundle)
- IMAGE + MOTION을 씬 단위로 묶어야 함
- 파일 간 점프는 인지 부하 증가
- **한 씬 완료 → 다음 씬** 흐름이 자연스러움

### 3. 체크리스트 필수
- 8개 씬 + 앵커 2개 = 복잡함
- 진행 상황 추적 필요
- **체크리스트로 현재 위치 파악**

### 4. 복사 UX
- 프롬프트 블록마다 복사 버튼
- MD 뷰어나 웹 도우미에서 구현
- **원클릭 복사가 핵심**
