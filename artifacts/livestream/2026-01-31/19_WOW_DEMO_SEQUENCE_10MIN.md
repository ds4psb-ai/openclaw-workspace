# 10분 ‘와…’ 데모 시퀀스 (OpenClaw × NotebookLM × Antigravity)

> 표기 메모: OpenClaw의 이전 명칭은 MoltBot입니다.

목표: 중년 사장님·자영업자·부업 관심자가 **“이건 장난이 아니네…”**라고 느끼게 만드는 장면만 보여준다. *(핵심: 기능 설명보다 ‘체감 장면’을 먼저 제시한다.)* 시간이 밀리면 설명을 늘리기보다 장면 수를 줄여서라도 이 순서를 지킨다(핵심 데모 우선).

운영 원칙: 라이브 중 실반영은 **드라이런(dry run) 확인 후 승인된 항목만 1회** 실행한다. 성공/실패와 무관하게 **같은 작업의 재실행(연타 포함)은 원칙적으로 금지**한다(중복 반영 방지). 실패 시에는 **2분 내** 플랜B로 전환한다. *(승인 전 반영 금지, 실행 직전 반영 대상(문서/페이지/브랜치) 10초 재확인, 부득이한 재시도는 Q&A 구간에서만 최대 1회 허용. 동일 요청을 표현만 바꿔 재요청하는 것도 재실행으로 간주. 본편에서는 연속 재시도 금지.)*

## 시퀀스(10분 타임라인)

### 00:00–01:00 훅 (말로만)
- 멘트: “이건 챗봇이 아니라 **내 PC를 실제로 움직이는 비서**예요. 메신저에서 한 줄 던지면, 드라이런으로 먼저 확인하고 승인된 작업만 문서/블로그/홈페이지로 반영돼요(실반영은 작업 항목당 1회).”
- 운영 메모(권장): 훅 시작 시점에 `__:__ 오프닝 훅` 한 줄만 메모해 두기(영상 재생 시간 기준, 종료 후 챕터 정리 속도 향상).

### 01:00–04:00 (장면 1) NotebookLM ‘브랜드 브레인’ 3분 데모
- 스토리: 바이럴 방/채널의 기존 글/스크립트/홍보 문구를 ‘소스’로 넣으면, NotebookLM은 **소스 기반으로만** 답해서 톤이 안 깨짐.
- (업그레이드 포인트) 여기서 바로 **스토리보드 표(timecode/shot_goal)**까지 뽑아내면 ‘기획→제작’이 끊김 없이 이어져 **감탄 포인트(‘와’ 순간)**가 생긴다.
- 임팩트 한 줄: “프롬프트를 사람이 관리하는 게 아니라 **NotebookLM이 브랜드 브레인**이 된다.”
- 시연 포인트(화면)
  - NotebookLM에 소스 체크박스로 포함/제외 보여주기(공식 기능)
  - Chat에 질문 1개:
    - “오늘 라이브 요약을 ‘중년 사장님’ 타깃으로 6문장으로 써줘. 마지막은 상업성 티 안 나게.”

### 04:00–07:00 (장면 2) OpenClaw: 텔레그램 한 줄 → ‘게시/배포 초안’ 생성(승인 후 1회 반영)
- 스토리: “배포해줘” 한 줄이 업무 지시서로 변환되고, Git/Notion/블로그/홈페이지 업데이트 **초안 작업 큐**가 자동 생성되는 장면.
- 임팩트 한 줄: “직접 쓰는 시간보다 **‘올려줘’라고 말하는 시간이 더 짧다**.”
- 시연 포인트(화면)
  - 텔레그램에서 봇에게 명령(예시, **드라이런(dry run) 결과를 먼저 확인한 뒤 승인된 항목만 실반영(항목당 1회)**):
    - “NotebookLM 최신 요약을 가져와서: 1) 홈페이지 공지 섹션 업데이트 문구 작성 2) 고정댓글/설명란 문구 업데이트 3) Git 커밋 메시지까지 만들어줘.”
    - (안전장치) 실반영 전에 “지금 바로 반영할까요?” 확인 질문 1회 후 실행(라이브 중 오반영/오적용 방지, 중복 실행 금지). **승인 직전에는 반영 대상(문서/페이지/브랜치) 한 줄 요약을 다시 읽고 실행.**
    - (운영 옵션) 라이브 상황이 불안정하면 **실반영은 생략하고 드라이런 결과 화면만** 보여준 뒤, 실제 반영은 종료 후 1회만 진행한다(라이브 중 같은 반영 재요청/재실행 금지).
  - 결과물: Git diff/commit 준비 화면 또는 Notion/문서 생성 결과 중 **하나만** 명확하게 보여주기 *(시간 초과 방지를 위해 1개만 선택하고, 나머지는 Q&A에서 언급만 하며 본편에서는 재시연하지 않기. 둘 다 본편에서 시연하지 않기).*
  - 선택 기준(권장): **시청자가 즉시 결과를 체감할 수 있는 화면**을 우선 노출(성과 인지 속도↑)
  - (운영 가드) 결과 화면을 보여준 뒤 **20초 안에** 다음 세그먼트(무드보드)로 전환해 리듬을 유지
  - (흐름 가드) 화면 전환 후에는 같은 단계로 되돌아가 재시연하지 않고, 질문은 Q&A 큐로 넘긴다
  - 1회 실행 가드레일(운영): **같은 명령 재실행 금지**, 승인 문구 확인 후 1회만 반영, 실패 시 2분 내 즉시 플랜B 전환
  - 승인 대기 지연 대응: 승인/확인 응답이 10초 이상 지연되면 실반영을 멈추고 **드라이런 결과 화면만 먼저 설명**한 뒤, 재실행은 Q&A 구간에서만 최대 1회 시도
  - (중복 방지) 같은 작업을 표현만 바꿔 다시 요청하지 않기(예: ‘다시 반영’/‘한 번만 더’/‘재적용’ 모두 재실행으로 간주)
  - (권장) 드라이런 결과 핵심 화면 1장을 즉시 캡처해 두기(종료 후 정리/후속 공지에 재사용)
  - 실행 로그(권장): 반영 직후 `KST HH:MM 반영 완료` 또는 `KST HH:MM Plan B 전환` 한 줄 기록

### 07:00–08:00 (장면 3) 무드보드: 60초 스타일 합의 (‘거장 DNA’ 시각화)
- 스토리: 키워드만으로 **이미지/색/구도**가 빠르게 정리되면 ‘미학’이 갑자기 쉬워짐.
- 임팩트 한 줄: “감으로 고르는 게 아니라, **보드로 합의**한다.”
- 시연 포인트: 무드보드에서 보드 1개 만들고 ‘조금 더 어둡게/더 미니멀하게’ 같은 자연어 수정 1회.

### 08:00–09:00 (장면 4) Antigravity: 공지 섹션/랜딩 ‘즉시 반영’
- 스토리: 라이브 중 바꾼 문구/섹션이 **홈페이지에 즉시 반영**되는 장면이 신뢰를 만든다.
- 임팩트 한 줄: “이제 업데이트는 ‘개발’이 아니라 **대화**다.”
- 시연 포인트
  - 공지 섹션(세션 요약/핵심 3파트/툴) 업데이트
  - (가능하면) Polar 버튼/안내 섹션이 노출되는 것까지

### 09:00–10:00 마무리 훅(오디오 팟캐스트로 확산)
- 스토리: 라이브가 끝나면 NotebookLM Audio Overview로 “오늘 방송 2분 요약(Brief)”을 뽑아 바이럴 방에 공유한다(가능하면 **종료 후 10–15분 내**).
- 임팩트 한 줄: “라이브가 끝나도 **AI가 후반 작업을 이어줘서** 바이럴이 계속 돈다.”
- 시연 포인트
  - Audio Overview 포맷(Brief/Deep Dive 등) 선택 화면을 짧게 보여주기
  - 마무리 멘트 고정: “방송 끝나고 2분 요약 오디오를 방에 바로 공유할게요.”
  - 실패 대비 멘트(대체): Audio Overview 생성이 지연되면 “오디오 요약은 종료 후 15분 내 커뮤니티에 업로드하고 링크를 고정댓글에 추가하겠습니다.”로 마무리
  - (권장) Audio Overview가 15분 내 준비되지 않으면, 같은 핵심을 담은 **텍스트 6문장 요약**을 기존 고정댓글에 1회 편집해 먼저 반영하고 오디오는 준비 즉시 링크만 추가
  - (운영 안전) 텍스트 요약을 올릴 때도 **기존 고정댓글 1회 편집**으로만 반영(새 댓글 재작성 금지, 중복 게시 방지)
