# OpenClaw (구 MoltBot) 2026 사용 사례 (라이브에 넣을 한 문단 + 안전 가이드)

## 라이브 30초 요약 (복사/붙여넣기)
> 표기 팁(권장): 라이브에서는 첫 1회만 **"OpenClaw (구 MoltBot)"**로 소개하고, 이후에는 **OpenClaw**로 통일하면 시청자 혼선을 줄일 수 있습니다.

- "OpenClaw (구 MoltBot)는 텔레그램 등 메신저를 **AI 에이전트의 리모컨**으로 바꿔주는 오픈소스 게이트웨이입니다. 공개 튜토리얼, 공식 문서, 커뮤니티 사례 전반에서 ‘폰에서 명령 → 서버에서 실행’ 패턴이 일관되게 확인됩니다. 오늘 시연도 같은 철학을 따릅니다. **자동화는 데모를 넘어 운영(로그/스케줄/버전/권한)까지 포함될 때** 실전에서 힘을 발휘합니다."

## 근거 링크(검증/업데이트용)
- MiniMax 튜토리얼(텔레그램에 OpenClaw 연결; 문서 내 명칭이 MoltBot이어도 동작 철학은 동일): https://platform.minimax.io/docs/solutions/moltbot
- OpenClaw 텔레그램 문서(privacy/admin/requireMention 등): https://docs.openclaw.ai/channels/telegram
- OpenClaw GitHub(릴리즈/변경 이력 확인): https://github.com/openclaw/openclaw
- 명칭과 운영 기준은 OpenClaw **공식 문서**를 최우선 기준으로 유지합니다.
- 구 MoltBot 표기는 과거 자료 검색/검증용으로만 참고하세요(혼선 방지).

## 명칭 혼선 방지(짧게)
- 자료/블로그에 남아 있는 **MoltBot** 표기는 이전 명칭이고, 현재 명칭은 **OpenClaw**입니다. *(검색 시에는 `OpenClaw`, `MoltBot`를 함께 쓰면 과거 자료까지 더 잘 찾을 수 있습니다.)*
- 라이브에선 첫 1회만 **OpenClaw (구 MoltBot)**로 소개하고, 이후엔 **OpenClaw**로 통일(슬라이드/자막/채팅 고정문구도 동일 규칙 적용).

## 안전 가이드(짧게)
- 프라이버시/권한:
  - 그룹에서 멘션 없이 동작하려면 Telegram BotFather의 `/setprivacy`를 `Disable`로 설정하거나, 봇에 관리자(admin) 권한을 부여해야 합니다(설정 변경 후 그룹 재초대가 필요할 수 있습니다).
- 운영/보안(기본값은 “거절”, 필요한 것만 허용):
  - 토큰/키는 절대 노출 금지(레포/스크린 공유/OBS 소스/로그 캡처 시 특히)
  - 메신저 명령은 **allowlist + 승인(approval) + `requireMention`/`prefix` + 드라이런(dry run) 가드레일**을 먼저 적용한 뒤, 작은 범위에서 시작합니다.
  - 데모는 가능하면 **데모 전용 계정/권한**으로 분리해 운영하고, 개인/운영 계정 권한은 라이브 화면에서 직접 사용하지 않습니다.
  - **1회 실행 원칙(한 번에 하나만 실행 → 결과 확인 → 다음 실행)**을 지키고, 처음 1–2회는 **읽기 전용 명령으로 리허설**한 뒤 진행합니다.
  - 외부 공개 대시보드 금지(라이브 데모 포함, 로컬/사설망 권장). 데모 계정이라도 접근 제어 없는 URL/초대 링크는 공유하지 않습니다.
  - 라이브 시작 전 1분 점검: 화면 공유/OBS 소스의 토큰·환경변수·터미널 히스토리·브라우저 자동완성 노출 여부를 확인합니다.
  - 송출 직전 비공개 개인 채팅에서 테스트 1회(의도한 채널/권한/`prefix` 확인) 후, 본 방송 채팅에서만 실행합니다.
  - 테스트 메시지는 짧고 비파괴 명령으로 제한(예: 상태 조회 1회)하고, 성공 로그 확인 후에만 다음 액션을 진행합니다.
  - 라이브 데모에 쓴 토큰/키는 종료 후 즉시 회수(또는 재발급)해 재사용 위험을 줄입니다.
