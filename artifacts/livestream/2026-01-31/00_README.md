## 핵심 규칙 (혼동 방지, 10초)
- **챕터/타임스탬프:** 영상 재생 시간 `__:__`만 (첫 줄은 `00:00`, 줄 맨 앞 공백/탭/불릿 없이, 줄 사이 빈 줄 없이 입력, 자동 번호매김 끄기)
  - `MM:SS`가 기본이고, 길면 `H:MM:SS`(또는 `HH:MM:SS`)도 허용(핵심: KST와 섞지 않기)
  - 문서 내 `__:__` 표기는 **영상 재생 시간 메모용 플레이스홀더**입니다. (KST 아님, 실제 시계값 입력 금지)
- **운영 로그/업데이트 시각(시계 시간):** `KST HH:MM`만 (접두어 `KST` 필수, 24시간제, 예: `KST 09:05`; 자정은 `KST 00:00`)
- **형식 통일:** `KST 9:5`처럼 쓰지 말고, `KST 09:05`처럼 `HH:MM` 두 자리 형식으로 기록(앞자리 0 유지 · 예: `KST 00:05`, 접두어 `KST` 생략 금지)
- **자정 표기:** `KST 00:00`만 사용(`KST 24:00` 금지, 날짜 경계 혼선 방지)

## 패닉 모드(30초)
- **먼저 오늘이 라이브 당일인지 확인(KST 날짜 기준):** 당일이 아니면 `KST 13:55` 멘션 단계는 스킵하고 리플레이 정리 동선만 실행. (**YouTube Studio 상태가 `진행 중` 또는 `Ended(종료됨)`이면, 로그 유무와 무관하게 멘션은 즉시 스킵**. 멘션 전송은 라이브 시작 전에만 1회 허용하며, **YouTube Studio 상태가 `Scheduled(예정됨)`일 때만 시작 전으로 간주**합니다. `13:55`를 넘겼더라도 **YouTube Studio에서 시작 버튼을 누르기 전**이면 누락 보완으로 1회 전송 가능)
  - (결정식) 멘션 전송 = **라이브 당일(KST) AND 미전송 AND 멘션 완료 로그 없음 AND 라이브 시작 전(YouTube Studio 상태가 `Scheduled(예정됨)`)**
  - (체크 순서) **당일 여부(KST) → 멘션 완료 로그 유무 → YouTube Studio 상태(Scheduled/진행 중/Ended)** 순서로만 판단(순서 고정, 중간 단계 생략 금지)
  - (판단 기본값) 위 순서에서 하나라도 애매하면 **중복 전송 방지를 위해 즉시 스킵(전송하지 않음)**
  - (원칙) 멘션은 **당일 1회만**. 라이브 시작 후 누락을 알아도 추가 전송하지 않기.
  - (한 줄 기억) **당일 아님/이미 전송/완료 로그 있음/시작 후** 중 하나라도 해당되면 멘션은 즉시 스킵(판단 애매 시에도 스킵).
  - (추적) 멘션을 보냈다면 **전송 직후 30초 내** `KST HH:MM 멘션 완료` 로그를 **`ZZ_LAST_AUTOLOG.md` 한 곳에만 한 줄** 남기기(중복 기록 금지, 당일 1회만 기록, 재전송 판단 기준으로 사용). 다른 문서에는 기록하지 않기.
  - (경계 시간 주의) 자정 전후(00:00 근처)에는 로컬 표기가 헷갈릴 수 있으니, 판단 기준은 항상 **현재 KST 날짜**로 고정

  - (집중 유지) 진행 중에는 새 탭/문서를 계속 열지 말고, 위 3개 안에서만 해결한 뒤 종료 후 정리
- **리플레이 정리 모드(라이브 당일이 아니거나 라이브가 이미 시작된 경우)**: `KST 13:55` 멘션 단계와 시작 전/진행 중 운영 체크를 스킵하고, 종료 직후 동선(`35_TIMESTAMP_TEMPLATE.md` → `20_YT_TITLE_DESC_PIN.md` → `90_POST_LIVE_FOLLOWUP.md`)만 실행(**`10_KAKAO_ALL_MENTION.md`는 열지 않음**. 멘션 로그(`ZZ_LAST_AUTOLOG.md`)는 신규 작성/수정/삭제 없이 기존 로그를 그대로 유지. 재전송 금지. 즉, 멘션 관련 신규 행동은 모두 금지. 판단이 애매하면 즉시 이 모드로 전환)
  - (고정) 리플레이 정리 모드에서는 멘션 관련 체크/기록을 모두 `N/A`로 보고, `종료 직후` 동선만 완료한다(멘션 로그 신규 작성/수정/삭제 금지).
  - (판정 기준) ‘라이브 시작 후’ 여부는 YouTube Studio 상태(`진행 중` 또는 `Ended(종료됨)`) 기준으로만 판단하고, 추정(딜레이 체감·채팅 반응)으로 결정하지 않기
  - (시작 전 기준) YouTube Studio 상태가 `Scheduled(예정됨)`일 때만 ‘시작 전’으로 간주(모호하면 시작 후로 간주해 스킵)

  - (빠른 동선) 리플레이 정리 모드에서는 **`35_TIMESTAMP_TEMPLATE.md` → `20_YT_TITLE_DESC_PIN.md` → `90_POST_LIVE_FOLLOWUP.md`** 순서만 고정 실행(중간 되돌아가기/재수정 루프 금지)
  - (순서 고정) 리플레이 정리 모드에서도 챕터 반영은 **기존 고정댓글 1회 편집 → 설명란 1회(총 2회)**로 마무리(한쪽만 반영하고 끝내지 않기, 각 단계 저장 확인 후 다음 단계로 이동)

## 운영 원칙(무한 루프 방지)
- 문서 v1 → (필요 시) 테드 한 줄 피드백 → v2에 1회 반영 후 종료(과다 수정 금지, **Writer/Reviewer 수정 루프는 회차당 최대 1회만**, 동일 루프 내 추가 수정은 금지하고, 다음 루프로 이월). 단, **명확한 오류(깨진 링크/치명 오탈자)**는 예외로 1회 즉시 보정 가능하며, 보정 사유는 한 줄로 기록.
- 방송 중에는 문서/링크를 정리하려고 멈추지 말고, **메모만**(타임스탬프/플랜B 전환 시각). 종료 직후 `35_TIMESTAMP_TEMPLATE.md`에 10–15분 안에 1회 반영.
- 데모가 막히면 **2분 내** 원인 확인만 하고, 안 풀리면 즉시 `50_DEMO_PLAN_A_B.md`의 플랜B로 전환.
- CTA는 **엔딩 1회만**. “판매”가 아니라 **필요한 분만 확인할 수 있게**(링크/가격은 설명란/고정댓글, 말은 최소).
- 고정댓글은 **방송 중 1회(링크 1개)**만 먼저 붙이고, **정리/타임스탬프 업데이트는 종료 직후 1회**로 마무리(운영 중 과다 수정 금지).
