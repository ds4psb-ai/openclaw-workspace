# One-screen Ops Cheat Sheet (라이브 중 이 한 장만 켜두기)

## TL;DR (진짜 급할 때)
- **챕터/타임스탬프는 `__:__`만** (영상 재생 시간, 00:00 기준)
- **운영 이벤트/업데이트 로그는 `KST HH:MM`만** (시계, 접두어 `KST` 꼭)
- (기준 꼬임 방지) **새로고침/리플레이 모드 전환 등으로 기준이 리셋되면**, `KST HH:MM 기준 리셋(새로고침/모드 전환)` 1줄만 찍고 계속
- **유튜브 설명란/고정댓글에 챕터를 붙여넣을 때는 `00:00 ...` 라인만 연속으로 붙여넣기** *(첫 줄은 반드시 `00:00`, `KST ...` 줄/업데이트 문구는 챕터 블록 밖으로 분리)*
  - 앞 공백/탭 금지, **불릿(-/•) 금지**
  - 빈 줄/구분선/설명 문장/`KST ...` 로그 없이, **`00:00` 포함 최소 3줄 이상(운영은 6줄 이상 권장)**
  - 복붙 직전 챕터 블록의 **맨 위/맨 아래 불필요한 공백 줄** 제거(인식 안정)
  - (앱 자동정리 주의) 메모앱/문서앱이 공백을 자동 정리해도, 최종 입력창에서 `00:00` 라인 연속 상태를 1회만 다시 확인
  - (모바일 복붙 주의) 붙여넣기 후 `00:00` 앞에 보이지 않는 공백이 들어갈 수 있으니, 첫 줄 커서를 맨 앞으로 이동해 1회 확인
- **막히면 2분 컷(원인 확인만) → 플랜B(Plan B) 즉시 전환**: `50_DEMO_PLAN_A_B.md` *(2분 넘기면 흐름이 무너짐 → 원인 집착 금지, 바로 전환. 휴대폰 2분 타이머를 실제로 켜두면 더 안전)*
- **라이브 중엔 `35_TIMESTAMP_TEMPLATE.md` 수정 금지**(메모앱에 `__:__`만 기록 → 종료 직후 1회 반영)
- (종료 순서) **YouTube Studio에서 스트림 종료(Ended) 확인 → OBS 로컬 녹화 OFF** 순서 고정(역순 금지, 종료 누락/파일 손상 방지)
- (종료 직후 챕터 반영) **고정댓글 1회 → 설명란 1회** 순서로 같은 챕터 블록을 동기화(불일치/중복 수정 방지)
- (저장 누락 방지) 설명/고정댓글 수정 직후 **Save/저장 버튼 비활성화**를 1초 확인하고 다음 동작으로 이동
- (링크 안정성) 고정댓글의 자료 링크는 **`https://...` 단독 한 줄**로 유지(라벨/불릿/백틱 없이)
- (사전 동선) **KST 13:55 카톡 전체 멘션 복붙(1회, 이미 전송했으면 재전송 금지)**: `10_KAKAO_ALL_MENTION.md`
- (리플레이용) 최종 챕터 반영 후 **설명란 챕터 인식(첫 줄 `00:00`)만 1회 확인**(공유/검색 안정)
- (반영 확인) 챕터 저장 후 **1–3분 대기 → 설명란 기준으로 챕터 1개 클릭 테스트 1회만**(저장 직후 미반영 오해/과다 재수정 방지)
- (반영 지연 대응) 저장 직후 안 보여도 **즉시 재수정하지 말고 1–3분 대기 후 1회만 새로고침**(중복 수정/버전 꼬임 방지)
- (추가 원칙) 챕터/설명란은 **같은 내용으로 연속 저장 반복 금지**(반영 지연을 수정 누락으로 오해하는 사고 방지)
- (종료 직후 동선) **`35_TIMESTAMP_TEMPLATE.md` 정리 → `20_YT_TITLE_DESC_PIN.md` 반영 → `90_POST_LIVE_FOLLOWUP.md` 후속 실행** 순서로 이동(탭 왕복 최소화)

## 시간 표기 규칙(헷갈림 방지)
- **챕터/타임스탬프 = `__:__` (영상 재생 시간, 00:00 기준)**
  - 보통 `MM:SS`, 길면 `H:MM:SS` / `HH:MM:SS`도 OK (문서 안에서만 일관되면 OK)
  - (주의) 라이브 레이턴시 때문에 **실제 시계(KST)**와 **영상 재생 시간**은 항상 다를 수 있음 → 챕터는 무조건 **영상 재생 시간**만.
  - (주의) 라이브 중 **새로고침/리플레이 모드 전환**을 하면 재생 시간이 점프하거나 기준이 달라져 헷갈릴 수 있음 → **타임스탬프 기록용 화면은 가능하면 유지**하고, 새로고침이 필요하면 그 시각을 `KST HH:MM`으로 한 줄만 남겨두기.
    - (복붙 1줄) `KST HH:MM 새로고침/모드 전환(기준 리셋)`
  - (유튜브 챕터 자동 인식 최소 조건)
    - 첫 줄은 **반드시 `00:00`**
    - 최소 **3줄 이상**(운영은 6줄 이상 권장)
    - 챕터 간격은 가능하면 **10초 이상** 유지(너무 촘촘하면 인식/가독성이 떨어질 수 있음)
  - (입력 형태) 유튜브 고정댓글/설명란에 최종 입력할 때는 **불릿(-/•) 없이** `00:00 ...`을 **각 줄 단독 라인**으로 붙여넣기(챕터 인식/클릭 안정)
    - (중요) **들여쓰기(앞 공백/탭) 금지** — 줄 맨 앞부터 `00:00`로 시작
    - (추가 주의) **코드블록(백틱)으로 감싸지 말기** — 챕터 인식/모바일 클릭성이 떨어질 수 있음
    - (추가 주의) **챕터 블록 안에 `KST ...` 운영 로그를 섞지 말기** — 필요하면 빈 줄로 분리해서 아래에 따로 적기
    - (추가 주의) 챕터(00:00… 라인들)는 **빈 줄/설명 문장/구분선(예: `— ... —`) 없이 연속으로** 붙여넣기(인식 안정)
    - (추가 팁) **챕터 제목은 짧게(한 줄), 특수문자/이모지 최소화** — 모바일에서 가독성/클릭성이 더 안정적
    - (운영 팁) 챕터 인식은 보통 **설명란에 붙였을 때 가장 안정적**임. 고정댓글은 “복붙/공유용”으로 쓰고, 리플레이 공개용 최종 반영은 **설명란에도 1회** 붙여두는 걸 권장.
- **운영 이벤트 = `KST HH:MM` (시계, 접두어 `KST` 꼭 붙이기)**
  - 예: `KST 09:05 자료 링크 고정댓글 게시` *(시각은 `09:05`처럼 **앞 0 유지 권장**)*

## (복붙용) 라이브 중 메모 템플릿
- 챕터 메모(영상 재생 시간): `__:__ 무엇을 했는지(짧게)` *(예: `00:00 오프닝` / `12:34 WOW 데모`)*
- 운영 로그(KST 시계): `KST HH:MM 무엇을 업데이트/확인했는지` *(예: `KST 17:05 고정댓글 링크 1개 게시`)*
- 플랜B 전환(옵션): `플랜B 전환 __:__ (사유 1단어)`
- (기준 꼬였을 때/리셋) 새로고침/모드 전환으로 재생 시간이 헷갈리면:
  - **그 순간을 `KST HH:MM 새로고침/모드 전환`으로 1줄 기록**
  - 이후엔 **새 기준으로 그냥 계속 `__:__`만** 기록(중간에 “정리”하려다 흐름 끊지 않기)

### (복붙/예시) 메모앱에 그대로 쌓을 ‘평문’ 형태
> 아래는 메모앱에 쌓기 좋은 예시.
> - 문서에서 예시 표기를 위해 `백틱`을 썼더라도, **실제 복붙은 백틱 없이 평문으로** 붙여넣기.

**(예시) 유튜브 챕터용으로는 아래 3줄(연속 라인)만 복붙**:

00:00 오프닝
12:34 WOW 데모
25:10 Part 1

> 주의: 위는 “형태 예시”라서 3줄만 넣었습니다.
> 실제 업로드/리플레이용 최종 챕터는 **`00:00` 포함 3줄 이상(권장 6줄 이상)**을 권장합니다.

(아래부터 운영 로그: KST)
(안내) 이 줄은 메모앱 참고용입니다. 유튜브 챕터에는 붙이지 말고, `00:00 ...` 라인들만 연속으로 선택해 복붙하세요.
KST 17:05 고정댓글 링크 1개 게시

> 메모앱에는 `__:__`와 `KST ...`를 같이 쌓아도 OK.
> 다만 **유튜브 챕터로 붙일 때는 `00:00 ...` 라인만 선택해서**(연속 라인으로) 붙여넣기 — `KST ...` 라인/구분선/빈 줄/설명 문장 포함 금지.

### (예시) 유튜브에 붙여넣을 챕터 형태(불릿/들여쓰기 없이, 각 줄 단독)

## Q&A 운영(흐름 유지)
- 질문은 채팅에 **`Q:`로 시작**하게 요청: `Q: 직무 / 상황 / 원하는 결과`
  - (복붙 1줄) `Q: 직무 / 상황 / 원하는 결과 (1줄)`
  - (질문이 길어지면) “감사합니다 — 채팅이 너무 빨라서요. `Q:`로 시작해서 `직무 / 상황 / 원하는 결과`만 1줄로 다시 한 번만 부탁드릴게요.”
- **질문 1개당 60–90초 타이머**(결론 1줄 → 이유 1줄 → 다음 액션 1줄)
- 타이머가 울리면 **결론 1줄만 더 말하고 바로 컷**("다음 질문 갈게요") — 흐름 유지
- (운영) 채팅 공지 1줄을 **고정댓글에 1회** 붙여두기(평문 추천): `Q: 직무 / 상황 / 원하는 결과 (1줄)`
- 자세한 스크립트/선별 규칙: `60_QA_PROTOCOL.md`

  - (가독성 팁) `업데이트: KST ...` 같은 운영 로그 라인은 **챕터 블록과 빈 줄로 분리**(챕터 인식 사고 방지)
  - (실수 방지) 고정댓글을 수정/업데이트했다면 **핀(고정) 상태가 유지되는지** 10초 확인(수정하다가 고정이 풀리는 사고 방지)
- 마지막으로 운영 로그 `KST HH:MM` 1줄(예: `KST 18:12 고정댓글/설명란 업데이트 완료`)

## 저장/반영 확인(10초)
- 고정댓글/설명란 수정 후: **저장 버튼 비활성화 확인 → (필요 시) 새로고침 1회**(정말 저장/고정됐는지 확인)
- (핀 사고 방지) **고정댓글 수정 후에는 댓글 목록 상단에서 ‘고정됨’ 배지를 1회 다시 확인**
- (추가 팁) 고정댓글이 갑자기 안 보이면 **댓글 정렬이 ‘인기순/Top comments’인지** 확인하고, 필요 시 새로고침 1회
- 반영/챕터 인식은 **1–3분 정도 지연**될 수 있음(조금 기다렸다가 1회만 확인)
- 챕터 인식이 안 되면: **(1) 챕터를 설명란에 먼저 붙이기 (2) 1–3분 기다리기 (3) 새로고침 후 1개 클릭 테스트**
- 5분 이상 반영이 없으면: **챕터 라인(00:00…)만 남겨 임시 저장 → 1분 뒤 다시 제목 텍스트 추가**(인식 문제 분리)
- (저장 누락 방지) 설명란/고정댓글 수정 후에는 **Save/저장 버튼이 비활성화됐는지** 1초 확인(저장 안 눌러서 반영 누락되는 사고 방지)
- 가능하면 **시크릿/로그아웃 창에서 링크 1개 + 챕터 클릭 1개만** 테스트(권한/챕터 인식 사고 방지)

## (신규) 챕터 붙여넣기 전 5초 체크리스트
1) 첫 줄이 `00:00`인가?
2) 각 줄 맨 앞에 공백/탭/불릿이 없는가?
3) 코드블록(백틱)으로 감싸지 않았는가?
4) 챕터 라인들 사이에 **빈 줄/설명 문장**이 끼지 않았는가?
5) 챕터 블록(00:00… 라인들) 안에 `KST ...` 운영 로그가 섞이지 않았는가?

## 플레이스홀더 최종 체크(사고 방지)
- YouTube 입력란에서 한 번만 검색:
  - (팁) **Mac: `⌘F` / Windows: `Ctrl+F`**로 아래 키워드만 1회씩 검색하고 끝내기(과다 수정 방지)
  - `https://LINK_HERE` / `https://LINK_HERE_2`
  - `YYYY-MM-DD`
  - `KST HH:MM`
  - `__:__` *(타임스탬프를 실제 값으로 채우고도 플레이스홀더가 남았는지)*
  - `https://example.com` *(샘플 링크가 남았는지)*
  - `— ... —` *(구분선 플레이스홀더가 남았는지)*
