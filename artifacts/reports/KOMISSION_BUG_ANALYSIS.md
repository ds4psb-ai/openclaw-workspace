## 🚨 Critical: Celery Duplicate Execution (NEW!)

### Problem
After Phase 2 migration, `vdg_task_registry` (asyncio-based) is no longer used.
`analyze_full_pipeline_task` has **no duplicate prevention!**

### Risk
- Same item_id can be processed by multiple workers simultaneously
- DB conflicts, resource waste
- Potential data corruption

### Reproduction Scenario
1. User clicks "promote" button multiple times quickly
2. Multiple Celery tasks queued for same item_id
3. All workers start processing simultaneously

### Solution

**Option 1: Redis Lock (Recommended)**
```python
@celery_app.task(...)
def analyze_full_pipeline_task(self, item_id, ...):
    from redis import Redis
    redis = Redis.from_url(settings.REDIS_URL)
    lock = redis.lock(f"vdg:analyze:{item_id}", timeout=1500)
    
    if not lock.acquire(blocking=False):
        logger.info(f"Task already running for {item_id}")
        return {"status": "skipped", "reason": "duplicate"}
    
    try:
        # ... actual work ...
    finally:
        lock.release()
```

**Option 2: DB Status Check**
```python
async with AsyncSessionLocal() as db:
    outlier = await db.get(OutlierItem, item_id)
    if outlier.analysis_status == "analyzing":
        return {"status": "skipped", "reason": "already_analyzing"}
```

**Option 3: Celery Task Unique Key**
```python
from celery import Task
from celery.utils.log import get_task_logger

class UniqueTask(Task):
    def apply_async(self, args=None, kwargs=None, **options):
        lock_key = f"celery-once-{self.name}-{args[0]}"  # item_id
        if redis.exists(lock_key):
            return None
        redis.setex(lock_key, 1500, "1")
        return super().apply_async(args, kwargs, **options)
```

## ⚠️ Medium: Neo4j Silent Failure

### Problem
Neo4j connection check passes, but subsequent queries can still fail.
After 3 retries, data is lost (not synced to graph).

### Risk
- Graph data inconsistent with PostgreSQL
- Genealogy queries return incomplete data

### Solution
```python
async def sync_with_fallback(self, ...):
    try:
        await self._sync_to_neo4j(...)
    except Neo4jError:
        # Queue for later retry instead of giving up
        await retry_queue.add({"type": "neo4j_sync", "data": ...})
```

## ⚠️ Medium: VDG Timeout Edge Case

### Problem
- soft_time_limit: 20 minutes
- hard_time_limit: 25 minutes
- Long videos (3min+) + slow Gemini API = timeout risk

### Risk
- Analysis incomplete
- Item stuck in "analyzing" status (though Phase 2 helps with this)

### Solution
```python
def _get_dynamic_timeout(video_duration_ms: int) -> tuple[int, int]:
    """Dynamic timeout based on video length"""
    duration_min = video_duration_ms / 60000
    
    if duration_min <= 1:
        return (1200, 1500)  # 20/25 min
    elif duration_min <= 2:
        return (1500, 1800)  # 25/30 min
    else:
        return (1800, 2100)  # 30/35 min
```

## ⚠️ Low: Embedding Drift

### Problem
When embedding model is updated (e.g., gemini-embedding-001 → v2):
- New embeddings incompatible with old ones
- Vector similarity search returns wrong results

### Solution
```python
# 1. Version field in Neo4j
CREATE (comp:CompositionAnalysis {
    embedding_version: "gemini-embedding-001",
    embedding_vector: [...]
})

# 2. Migration script
MATCH (c:CompositionAnalysis)
WHERE c.embedding_version <> $new_version
SET c.needs_reembed = true

# 3. Background re-embedding job
```
