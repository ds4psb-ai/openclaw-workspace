## 3. Key Cypher Queries

### 3.1 Genealogy Tree (족보)

```cypher
MATCH path = (root:RemixNode {node_id: $node_id})
  -[:EVOLVED_TO*0..{depth}]->(descendant:RemixNode)
RETURN path
```

**Usage:** 특정 노드의 모든 자손 찾기

### 3.2 Successful Mutations (성공 변이)

```cypher
MATCH (template:RemixNode {node_id: $id})
  -[r:EVOLVED_TO]->(successful:RemixNode)
WHERE r.performance_delta CONTAINS '+'
RETURN r.mutation_profile, r.performance_delta
ORDER BY successful.view_count DESC
LIMIT 5
```

**Usage:** 성과가 향상된 변이 전략 찾기

### 3.3 Create EVOLVED_TO Edge

```cypher
MERGE (parent:RemixNode {node_id: $parent_id})
MERGE (child:RemixNode {node_id: $child_id})
MERGE (parent)-[r:EVOLVED_TO]->(child)
SET r.mutation_profile = $mutation_profile,
    r.performance_delta = $performance_delta,
    r.created_at = datetime()
```

**Usage:** 포크 시 계보 관계 생성

### 3.4 Vector Similarity Search (벡터 유사도)

```cypher
CALL db.index.vector.queryNodes(
  'composition_semantic_similarity',
  $limit,
  $queryVector
)
YIELD node, score
MATCH (kick:ViralKick)-[:HAS_COMPOSITION]->(node)
RETURN kick.kick_id, score
```

**Usage:** 3072-dim embedding으로 유사 구도 검색

### 3.5 Music Cluster Items

```cypher
MATCH (oi:OutlierItem)-[:USES_MUSIC]->(mc:MusicCluster {music_id: $id})
RETURN oi.item_id, oi.title, oi.view_count
ORDER BY oi.view_count DESC
```

**Usage:** 특정 음악 사용한 아웃라이어 찾기

## 4. Vector Index

FOR (comp:CompositionAnalysis)
ON comp.embedding_vector
OPTIONS {
  indexConfig: {

    `vector.similarity_function`: 'cosine'
