# T002 – Vivid 메가앱 UX 최적화: 감사(UX Audit) 플랜 (Draft)

작성: 보미 🐰  
업데이트: 2026-01-31 (KST)

## 목표
- “메가앱”의 핵심 플로우에서 **첫 성공(Activation)** 까지의 마찰을 줄이고, 재방문/생성 반복을 쉽게 만든다.
- 단기(P0): 온보딩→첫 생성→결과 확인/저장까지 **이탈률 감소**.
- 중기(P1): Dimension 앱 전환/탐색의 **인지 부하 감소**.

## 범위(가정)
- 제품: Vivid (Crebit Studio) 메가앱 UX
- 채널: Web(Desktop) 우선, Mobile은 2차

## 0) 필요한 입력(있으면 정확도 급상승)
- 현재 메가앱 IA/스크린샷/영상(3~5분)
- 실제 퍼널 데이터(온보딩→첫 생성 완료율, 평균 소요 시간)
- 신규 유저의 "첫 과업" 정의(예: DNA Lab에서 영상 분석 완료 / Story Engine에서 시나리오 1개 생성 등)

## 1) 핵심 유저 여정(가설)
1. Landing / 홈 진입
2. 온보딩(권한/계정/목표 선택)
3. 메가앱 선택(DNA Lab vs Story Engine vs Production Bridge)
4. 첫 과업 수행(업로드/프롬프트/설정)
5. 결과 확인(프리뷰/씬/버전)
6. 저장/공유/재실행

## 2) P0 이슈 체크리스트(즉시 개선 후보)
### A. 온보딩/진입
- [ ] 진입 옵션이 1개로 강제되어 있나? (초보/중급/고급 분기)
- [ ] 첫 화면에서 "무엇을 하면 되는지" 1문장으로 설명되는가?
- [ ] 샘플 데이터로 바로 체험 가능한가? (Value-before-signup)

### B. 첫 과업(Activation)
- [ ] 최초 1분 내 클릭/입력 포인트가 명확한가?
- [ ] 업로드/생성 대기 중 피드백(남은 시간/다음 행동)이 있는가?
- [ ] 에러/실패 시 복구 경로가 명확한가?

### C. 결과 화면
- [ ] 결과의 "다음 액션"(저장/변주/다음 단계)이 1~2개로 좁혀져 있는가?
- [ ] 버전/히스토리 관리가 사용자가 이해 가능한가?

### D. 과금/크레딧
- [ ] 크레딧 소모가 실행 전 명확히 보이는가?
- [ ] 결제/충전은 사용 흐름을 끊지 않고 맥락형으로 제공되는가?

## 3) 산출물(내가 만들 것)
- UX 감사 리포트(P0/P1/P2 우선순위, 예상 임팩트)
- 개선안(화면/컴포넌트 단위) 제안
- (가능하면) 최소 프로토타입/PR 제안 목록

## 4) 다음 액션
- 테드가 Vivid 메가앱의 “가장 중요한 첫 과업(Activation)” 1개만 지정해주면, 그 플로우 기준으로 P0 개선안부터 바로 구체화.
