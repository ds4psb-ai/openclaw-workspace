## 1. 자기 검증 (ThinkPRM 스타일)

### 언제 사용?
- 복잡한 분석/추론 답변 전
- 코드 작성 후
- 중요한 결정/추천 시

### 체크리스트
```markdown
□ 논리적 비약 없나?
□ 가정이 명시되어 있나?
□ 반례가 있을 수 있나?
□ 확신도는? (높음/중간/낮음)
□ 불확실한 부분 솔직히 말했나?
```

### 예시
```
[답변 전 자기 검증]
- 논리: A → B → C, 각 단계 타당함 ✓
- 가정: 사용자가 Python 3.x 사용 (명시 안 됨)
- 반례: Windows에서 경로 문제 가능
- 확신도: 중간
→ "Windows에서는 경로 확인 필요" 추가
```

## 2. 정체성 확인 (Identity Check)

### 언제 사용?
- 세션 시작 시
- 다른 에이전트 언급할 때
- 헷갈릴 때

### 체크리스트
```markdown
□ Runtime host 확인 (MacBook = 소미, vultr = 보미)
□ IDENTITY.md 이름/이모지 일치?
□ 메시지 폴더 방향 맞나? (to_somi = 받는 것, to_bomi = 보내는 것)
```

### 각인 문구
```
🐱 소미 = Mac = 테드 로컬 = 100.69.32.16
🐰 보미 = VPS = vultr = 100.109.36.63
```

## 3. 환각 방지 (Hallucination Prevention)

### 고위험 상황
- 날짜/시간 언급
- 숫자/통계 인용
- 외부 정보 (API 응답 등) 해석
- "~라고 했다" 류 인용

### 대응
```markdown
□ 출처 확인 가능? → 명시
□ 확인 불가? → "제가 기억하기론..." 또는 검색
□ 추측? → "아마도...", "~일 수 있음" 명시
```

```markdown
Q: 테드 텔레그램 ID는?

### 결과
- 통과: X/3
- 실패 원인: [기록]
- lessons/ 추가 필요?: [Y/N]
```

## 5. 메모리 정리 (MemoRAG 스타일)

### 주간 정리 체크리스트

```markdown
## MEMORY.md 정리

### 압축 대상
□ 중복 정보 → 병합
□ 오래된 정보 (>1달) → 요약 or 삭제
□ 완료된 태스크 → 삭제 or 아카이브

### knowledge/ 정리
□ 새 파일 인덱싱
□ 관련 파일끼리 related: 태그 연결
□ 오래된 lessons 중 일반화 가능한 것 → patterns로 승격

### 정리 후 커밋
git commit -m "🧹 주간 메모리 정리 YYYY-MM-DD"
```
